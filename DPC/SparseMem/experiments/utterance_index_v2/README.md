# SparseMem V2 发言级索引

在同一套冻结的记忆块上比较旧索引和发言级索引。V2 保留整块、L1 和 L2 的索引项及原向量，把每块最多两条关键句的入口换成覆盖原文的发言片段。短发言直接索引，较长发言按句子切分，超长单句按 MiniLM 的 96 Token 上限再切。入口保存原文片段、说话人、日期、会话、所属记忆和原文位置。整个过程新增生成式构建 Token 为 0。

两组使用同一份仅用户发言的历史缓存、同一个 MiniLM、BM25、RRF、Top-20、Reader 提示词和 4,096 Token 证据上限。Top-K 按记忆块计数。同一块的多个高排名发言仍可进入上下文，一个片段如果被已选的同来源完整发言包含，Reader 只收到完整发言。索引阶段不接收问题或评测标注，官方证据标注只用于输出诊断。当前轮比较的是发言级索引与相应的原文装配，后续可以单独比较上下文补全和实体扩展。

从 `DPC/SparseMem` 运行，默认只用本地模型重建一个历史索引并重放一题检索。使用不同目录保存不同的题目切片。需要生成回答时加 `--answer`，其 `hypotheses.jsonl` 可交给已有的 Qwen 评分工具。诊断输出记录标记发言片段覆盖、标记原文全文覆盖、索引条目和体积、检索耗时及 Reader 输入 Token。标记发言覆盖只能作为证据完整性的代理指标。

```sh
PYTHONPATH=. python3 experiments/utterance_index_v2/run.py --out runs/utterance_index_v2_smoke --limit 1
```

## 构建与索引的计数

Stage 1 按语义块生成 Memory Record，每条记录有一个 L0、L1 或 L2 加工等级和可追溯的原文指针。Stage 2 为这些记录建立检索入口。多个入口可以指向同一条记录，也可以分别命中不同的原文位置。Stage 3 按 `memory_id` 计算 Top-K，并保留预算内的多条原文证据。基于实体的跨会话补检和集合选择属于后续可独立比较的组件。

使用 LongMemEval-S 开发题 `0a995998` 做本地验证，原版检索重放与历史日志一致。

| 指标 | 原版 | V2 |
| --- | ---: | ---: |
| Memory Records（L0 / L1 / L2） | 135（47 / 81 / 7） | 135（47 / 81 / 7） |
| 原始用户发言 | 242 | 242 |
| 统一索引条目总数 | 464 | 824 |
| 最终 Top-K 记忆 | 20 | 20 |
| 进入上下文的标记发言 | 3 / 3 | 3 / 3 |
| 证据 Token | 4,042 | 4,063 |
| 索引文件大小（MB，十进制） | 5.28 | 9.35 |

V2 的 824 个索引条目中有 607 个发言片段入口。最终上下文包含 24 个命中入口所对应的内容，其中 5 条记忆各提供了多个命中入口。重新建索引用时约 4.2 秒，增量 MiniLM 编码工作量为 18,295 Token。该样本只验证索引、归并和证据装配，准确率尚待评分。
